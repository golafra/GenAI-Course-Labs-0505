# Spec: مدیریت و انتشار کنترل‌شدهٔ پست وبلاگ

**وضعیت:** تأیید آموزشی برای پیاده‌سازی فازبه‌فاز  
**ورودی محصول:** نویسنده‌ها پست خود را مدیریت می‌کنند؛ ویراستار پس از بررسی و تأیید منتشر می‌کند؛ بدون مجوز/تأیید، انتشار ممنوع است.

## Clarifications

- تأیید تاریخی پس از لغو مجوز تأییدکننده معتبر می‌ماند اگر محتوا عوض نشده باشد؛ مجوز فعلی منتشرکننده الزامی است.
- نسخهٔ اول فقط API است؛ UI وب خارج از Scope.

## User Stories

### US1 — نویسنده (P1)

ایجاد Draft، فهرست/جزئیات پست خود، ویرایش، حذف منطقی منتشرنشده، Submit برای بررسی.

**Acceptance (خلاصه):** مالکیت ثابت؛ عنوان/متن غیرخالی؛ نویسندهٔ دیگر به Draft دیگران دسترسی ندارد؛ Submit → `pending_review`.

### US2 — ویراستار (P1)

صف بررسی، Request Changes با دلیل، Approve غیرمالک، Publish با مجوز فعلی.

**Acceptance (خلاصه):** خودتأییدی ممنوع؛ تغییر محتوا تأیید را باطل می‌کند؛ Publish فقط روی تأیید معتبر محتوای فعلی.

### US3 — امنیت و عمومی (P1)

خواننده فقط Published می‌بیند؛ دور زدن Permission/Approval ممکن نیست؛ Published پایدار است؛ رقابت با Version/ETag.

## Functional Requirements (خلاصه)

| ID | نیاز |
|----|------|
| FR-001 | هویت و Permission فعلی برای هر عملیات مدیریتی |
| FR-002–005 | CRUD/Submit نویسنده با مالکیت و انتقال وضعیت |
| FR-006–009 | صف، برگشت، تأیید، انتشار ویراستار |
| FR-010–015 | رد غیرمجاز، Public فقط Published، رقابت، Idempotency محدود Publish |

## Out of Scope این نسخه

- صفحهٔ وب، پرداخت، جستجوی پیشرفته
- LLM / MCP / RAG (Feature جدا بعد از تکمیل این Spec)
